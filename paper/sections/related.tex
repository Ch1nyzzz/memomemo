\section{Related Work}
\label{sec:related}

\paragraph{Automated harness and prompt optimization.}
The idea of using LLMs to improve their own harness traces back to
prompt optimization: OPRO~\cite{yang2024opro} frames prompt engineering as
black-box optimization with LLM-generated candidates, while
EvoPrompt~\cite{guo2024evoprompt} couples evolutionary operators with LLM
mutation to search the prompt space. DSPy~\cite{khattab2023dspy} lifts the
abstraction from prompts to declarative pipelines, compiling module
signatures into optimized few-shot chains. Moving beyond prompts to
full harness code, ADAS~\cite{hu2024adas} introduces a propose--evaluate
loop in which an LLM proposer writes new agent programs from scratch each
iteration, searching over a growing archive of prior designs.
Meta-Harness~\cite{lee2026metaharness} extends this to file-level harness
optimization: the proposer (Claude Code) receives full filesystem access to
all prior candidates' source, scores, and execution traces, and edits
harness files in place. ACE~\cite{zhang2025ace} takes a complementary
perspective, evolving the agent's \emph{context} (system prompts and memory
playbooks) rather than the harness code itself, through generation,
reflection, and curation stages. Our work is most directly comparable to
Meta-Harness and ADAS: we adopt the same propose--evaluate outer loop but
focus on a previously unaddressed dimension---\emph{what the proposer
attends to}---introducing adaptive context-selection policies that manage
attention across iterations.

\paragraph{Evolutionary code search.}
FunSearch~\cite{romeraparedes2024funsearch} demonstrates that pairing an LLM
with an evolutionary algorithm can discover novel mathematical constructions,
using an island-based population and automated scoring to guide search.
AlphaEvolve~\cite{novikov2025alphaevolve} generalizes this to multi-file
codebases with a Gemini-powered coding agent, while
OpenEvolve~\cite{sharma2025openevolve} provides an open-source
reimplementation. ELM~\cite{lehman2023elm} formalizes LLMs as mutation
operators within evolutionary computation more broadly. These systems
optimize \emph{programs} (algorithms, heuristics) via evolutionary
selection pressure; our work optimizes \emph{agent harnesses} (memory,
retrieval, tool-use orchestration) via a propose--evaluate loop. The key
architectural difference is that evolutionary systems maintain explicit
populations and fitness-proportional selection, whereas our framework
maintains a Pareto frontier and manages a single proposer's attention window
at each iteration.

\paragraph{LLM agent architectures.}
Modern LLM agents augment base models with external memory, tool use, and
self-reflection. MemGPT~\cite{packer2023memgpt} introduces a virtual
memory hierarchy that lets agents manage their own context window through
explicit load/store operations. Reflexion~\cite{shinn2023reflexion}
equips agents with verbal self-reflection, accumulating textual feedback
across episodes. Voyager~\cite{wang2023voyager} builds an open-ended
agent with a growing skill library. SWE-agent~\cite{yang2024sweagent}
designs agent--computer interfaces optimized for software engineering tasks.
These systems are \emph{targets} of harness optimization---our benchmarks
evaluate optimized versions of MemGPT-style memory harnesses (LoCoMo,
LongMemEval) and SWE-agent-style coding harnesses (SWE-bench Verified).

\paragraph{Context utilization in long-context LLMs.}
Liu et al.~\cite{liu2024lost} show that language models disproportionately
attend to information at the beginning and end of their context window,
with retrieval accuracy degrading for facts placed in the middle. This
``lost-in-the-middle'' phenomenon motivates our progressive policy: by
starting with a narrow context (only the most relevant files and reference
iterations), we ensure that critical information occupies the positions
where the proposer LLM is most likely to attend to it. The bandit policy
addresses the same problem from a different angle, explicitly scoring files
by historical utility and concentrating high-value files in the prompt.

\paragraph{Multi-armed bandits for resource allocation.}
Our bandit policy builds on the UCB1 algorithm~\cite{auer2002ucb}, which
balances exploration and exploitation through an upper confidence bound on
each arm's estimated reward. We adapt this framework to file selection:
each workspace file is an arm, the reward signal is a rolling $z$-score of
harness performance after iterations that read the file, and a
Beta-smoothed prior prevents premature convergence on small samples. This
application of bandit algorithms to \emph{attention allocation} within an
optimization loop is, to our knowledge, novel.

\paragraph{AutoML and neural architecture search.}
The broader AutoML literature~\cite{he2021automl} addresses automated
algorithm configuration and architecture search through techniques ranging
from Bayesian optimization to evolutionary strategies. Our work can be
viewed as an instance of this paradigm applied to LLM agent harnesses,
with two distinguishing features: (i) the search space is defined by
natural-language code edits rather than a fixed configuration grammar, and
(ii) the search is conducted by an LLM proposer whose own attention is a
first-class resource to be managed.
