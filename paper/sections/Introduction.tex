\section{Introduction}
\label{sec:intro}

Agent \emph{harnesses}---the code that wraps a large language model
(LLM) into a working agent---are a major determinant of agent
performance. Two agents built on the same LLM but with different
harnesses can differ by as much as $6\times$ on the same
benchmark~\cite{tian2026swe}. This gap has motivated
\emph{automated harness optimization}: an outer loop in which an
LLM-driven proposer iteratively proposes candidate agents, prompts, or
memory components, and an evaluator scores each candidate to guide the
next proposal~\cite{romeraparedes2024funsearch,novikov2025alphaevolve,sharma2025openevolve,agrawal2025gepa,lee2026metaharness}.

Most prior approaches inherit the information bottleneck of text
optimization~\cite{hu2024adas,sharma2025openevolve,zhang2025ace}.
Feedback from previous runs is compressed into scalar scores, short
summaries, or the most recent candidate~\cite{novikov2025alphaevolve,agrawal2025gepa,lee2025feedback,madaan2023self,yang2023large}.
This compression removes details needed to trace downstream failures to
earlier harness decisions~\cite{lee2026metaharness}. Meta-Harness
addresses this limitation by replacing the proposer with a coding agent
equipped with developer tools and by exposing the full revision history
as a navigable filesystem~\cite{lee2026metaharness}. The meta-agent can
inspect raw code, execution traces, and diffs before proposing the next
edit.

Full access, however, is not equivalent to effective access. As the
optimization horizon grows, the filesystem contains an expanding set of
prior candidates, failed edits, traces, and summaries. The proposer must
then repeatedly determine which subset of this history is relevant to
the current failure. We therefore reframe automated harness
optimization as an \emph{online context curation} problem: before each
proposal, the optimizer must decide which prior iterations, trace
details, and workspace files should be made salient under the
proposer's limited inspection budget.

We introduce \textbf{\name}, a framework that treats this context
choice as a control variable in automated harness optimization. \name
sits between the optimization loop and the meta-agent, deciding which
historical evidence and file-level evidence should guide each proposal.
The framework supports two composable curation strategies. The
iteration-level strategy defines
the historical scope: it starts from a small labelled set of high- and
low-performing prior attempts and expands exposure when optimization
stalls. This strategy is sufficient to improve held-out performance in
our main comparisons. The file-level strategy can then be added to
reallocate the proposer's fixed read budget within the exposed
workspace, using delayed reward to prioritize files whose inspection has
correlated with productive edits.

This design does not require both strategies to be active. Rather, both
address the same inspection bottleneck at different granularities.
Iteration-level curation changes which parts of the search history are
available and labelled. File-level curation changes where the proposer
spends its bounded inspection effort inside the exposed workspace. Thus,
the two axes need not produce independent, monotonic, or uniformly
positive effects. They provide alternative and composable ways to move
the optimization loop along a cost--quality frontier.

We evaluate \name on three benchmarks spanning agentic software
engineering and long-horizon memory: SWE-bench~\cite{jimenez2024swebench},
LongMemEval~\cite{wu2024longmemeval}, and LoCoMo~\cite{maharana2024locomo}.
Across these benchmarks, adaptive context curation improves held-out
performance in most settings and introduces lower-cost operating points
on the cost--quality frontier. On SWE-bench Verified, the strongest
curated harness reaches 0.640 passrate on the full verified set,
compared with 0.440 for the source harness and 0.458 for the
full-context optimized baseline. Mechanistic analyses show that the
proposer reads roughly the same number of files per iteration; what
changes is the target. \name redirects this fixed inspection budget
from recency-biased browsing toward policy-labelled iterations and
utility-weighted files. These results suggest that managing what the
proposer attends to is a first-class design variable in automated
harness optimization.
